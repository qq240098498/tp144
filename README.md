# tp144 联赛赛程与积分核算台

一个本地小工具：把参赛球队、比赛场地与整季赛程登记进来，打完的场次记上比分，页面立刻算出积分、净胜球与名次。赛季打完按最终名次结出升级与降级清单，一键生成下一季的参赛球队与档位；上一季的赛程、积分与名次完整冻结，可随时切回去单独查看。左侧切视图、上方切赛季，右侧抽屉里增删改，所有数字都来自本机的数据文件，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 页面怎么用

左上角是**赛季选择器**，所有视图都随它切换；正在查看已结算的历史赛季时，页面顶部出现黄色“历史归档（只读）”横幅，赛程、球队、比分都只看不改。

左侧导航共六个视图：

1. **概览**：本季球队与场地数、赛程进度、已赛与待赛场次，最近五场赛果与积分榜前三；已结算赛季显示冻结的最终名次
2. **赛季**：当前季的升降级规则、最终名次与每支球队的去向；进行中的赛季在这里“按名次结算升降级”，已结算赛季可以“调整规则并重算去向”或“按升降级结果新建下一季”；下方是结算与规则变更记录
3. **球队**：“本季名册”显示档位、来源（创始 / 上季留级 / 低级别升级 / 季中增补）、状态与上季档位沿用说明；“候选名录”是不在本季名册里的球队（降级离队、升级离队与为下季预备的新队），新建下一季时从这里勾选升级队
4. **场地**：以卡片列出场地名称、城市、容量、可用日、本季主场球队与本季已排场次
5. **赛程**：按轮次与状态筛选，逐场列出日期、时刻、对阵、比分、场地与状态；未打完的场次可以点登记比分
6. **积分榜**：按名次列出场次、胜平负、进球失球、净胜与积分；已结算赛季按冻结名次展示，并多出一列“下季去向”（升级 / 降级 / 留级）

## 跨赛季怎么运转

### 1. 结算升降级

在“赛季”视图点**按名次结算**。抽屉里可以调整**升级队数**与**降级队数**，表格实时预览每支球队的去向；还有没打完的场次时会给出提示，必须勾选“照当前名次结算”才能确认。结算口径：

- 最终名次沿用积分榜口径：积分 → 净胜球 → 进球 → 队名
- 名次靠前的 N 队标记为**升级**（升入高级别，下季离队）
- 榜尾 M 队标记为**降级**（降入低级别，下季离队）
- 其余球队标记为**留级**
- **退赛队**不论名次一律按降级处理，且不占用降级名额
- 升级与降级名额之和不能超过参赛队数
- 结算后冻结一份最终名次表，之后随时可查，不再随任何操作变化

### 2. 规则调整与重算

已结算赛季点**调整规则并重算去向**，改动升级/降级队数时，抽屉顶部直接列出**哪些球队的归属变了**（例如“江城铁马：留级 → 升级”）；确认后更新去向并写入变更记录。最终名次表是冻结的，重算只改变去向标记。若后续赛季已经建立，页面会明确提示：重算只更新本季记录，不会改动后续赛季已定的名册。

### 3. 新建下一季

在已结算且没有后续赛季的赛季点**新建下一季**：

1. 填写新赛季名称
2. 选择**档位处理方式**：
   - **沿用上季档位**：留级队保住上季档位；升级队依次补进升级/降级队空出的档位，空档位补满后顺延到队尾；每个档位由谁空出、由谁补位，页面逐档列清；无人补位的档位明确标“本季留空”
   - **按最终名次重排**：留级队按最终名次从第 1 档顺排，升级队排在留级队之后
3. 从候选名录勾选升级入赛的球队
4. 表格里每支队的档位还能手动改；**档位冲突**（两支队占同一档）会被拦下并报错，改好才能建立

建立后自动切到新赛季：新赛季赛程为空、积分从零开始，球队的“来源”与“档位沿用说明”随名册带走。

### 4. 历史归档

- 已结算赛季的**赛程、比分、积分榜与最终名次完整保留**，用左上角赛季选择器切回去单独查看
- 历史赛季**只读**：新增/编辑/删除赛程、登记比分、改动名册档位都会被拒绝（接口返回 `SEASON_LOCKED`，页面不显示写操作按钮）
- 球队的身份信息（队名、简称、城市、主场）存在全局名录里，被历史引用过的球队不能删除，历史不会凭空消失
- 离队球队进入新一季的“候选名录”，以后可以勾选升级回来；已结算赛季期间仍可登记候选队

### 5. 候选球队

“新增球队”时可选：

- **加入本季名册**：直接成为本季参赛队，需要指定不重复的档位
- **仅登记为候选**：只进全局名录，不进任何赛季；等建下一季时勾选升级

## 积分与排序口径

- 只统计状态为已赛的场次，延期、取消与待赛的场次不计入
- 积分按胜一场 3 分、平一场 1 分、负一场 0 分累加，规则记在每个赛季的 `points` 里
- 名次依次比较：积分高的在前 → 净胜球多的在前 → 进球多的在前 → 队名排序
- 结算时冻结当季最终名次；积分表随登记比分实时重算（仅进行中的赛季）

## 登记口径

- 球队名称不重复、最长 24 个字；简称是两到四个大写字母且不重复；主场必须是已登记的场地
- 档位在 1 到 12 之间且同一赛季内不重复；单季名册最多 12 支，全局球队名录最多 30 支
- 场地名称不重复、最长 30 个字；容量在 100 到 200000 之间；至少要选一个可用日，且同一天不能重复勾选
- 赛程的轮次在 1 到 40 之间，日期要真实存在，开赛时刻写成两位小时加两位分钟；主队与客队不能是同一支，且都要在本季名册里
- 同一轮里一支球队只能出场一次；同一天同一块场地两场比赛之间至少隔两小时（场地留空时按主队主场算）
- 比分只在状态为已赛时填写，取值是 0 到 99 的整数
- 历史赛季引用过的球队或场地不能删除，页面会说明被多少个赛季引用

## 数据存储与升级

数据写在 `data/db.json`，顶层结构为 `{ meta, venues, teams, seasons }`：

- `meta.activeSeasonId`：页面当前查看的赛季
- `teams`：全局球队名录（身份信息），`venues`：全局场地
- `seasons[]`：每个赛季独立保存 `{ 名称、积分规则、升降级规则、名册(含档位/状态/来源/沿用说明)、赛程、冻结的最终名次、去向清单、变更记录 }`

落盘时先写临时文件再改名替换，写入过程中断不会把数据文件写坏；文件缺失时回落到初始数据。**旧版本（单赛季扁平结构）的数据文件首次读取时自动迁移**：球队身份进入全局名录，原档位、参赛状态转入第一季的名册，无需手工处理。

## 接口一览

| 方法   | 路径                                 | 说明                                   |
| ------ | ------------------------------------ | -------------------------------------- |
| GET    | /api/health                          | 服务状态检查                           |
| GET    | /api/summary                         | 概览数字、最近赛果与前三（支持 seasonId）|
| GET    | /api/seasons                         | 赛季清单                               |
| GET    | /api/seasons/detail                  | 赛季详情、冻结名次与去向（seasonId）   |
| POST   | /api/seasons/switch                  | 切换当前查看的赛季                     |
| POST   | /api/seasons/settle/preview          | 按规则预览名次去向与归属变化           |
| POST   | /api/seasons/settle                  | 确认结算 / 改规则重算去向              |
| POST   | /api/seasons/next/preview            | 预览下一季名册、档位与空位处理         |
| POST   | /api/seasons                         | 建立新赛季                             |
| GET    | /api/teams                           | 球队（scope=roster/outsider/all，seasonId）|
| POST   | /api/teams                           | 新增球队（joinMode=roster/candidate）  |
| PATCH  | /api/teams/:id                       | 修改球队身份，名册队可改档位与状态     |
| DELETE | /api/teams/:id                       | 删除球队（历史引用中不可删）           |
| GET    | /api/venues                          | 场地清单                               |
| POST   | /api/venues                          | 新增场地                               |
| PATCH  | /api/venues/:id                      | 修改场地                               |
| DELETE | /api/venues/:id                      | 删除场地（历史引用中不可删）           |
| GET    | /api/matches                         | 赛程清单（轮次、状态、关键词、seasonId）|
| POST   | /api/matches                         | 新增赛程                               |
| PATCH  | /api/matches/:id                     | 修改赛程                               |
| POST   | /api/matches/:id/result              | 登记比分，登记后自动标成已赛           |
| DELETE | /api/matches/:id                     | 删除赛程                               |
| GET    | /api/standings                       | 积分表；已结算赛季返回冻结名次与去向   |

除 `/api/health` 与清单接口外，读写接口都可用查询参数或请求体里的 `seasonId` 指定赛季；不传时作用于当前查看的赛季。接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`。

### 关键业务错误码

| 错误码                   | 含义                                                 |
| ------------------------ | ---------------------------------------------------- |
| SEASON_LOCKED            | 历史赛季只读，不能增删改                             |
| SEASON_UNFINISHED        | 还有场次没打完，需勾选确认后才能按当前名次结算        |
| RULES_OVERFLOW           | 升级名额加降级名额超过参赛队数                       |
| PRIOR_SEASON_NOT_SETTLED | 上一季还没结算，不能建立下一季                       |
| NEXT_SEASON_EXISTS       | 后续赛季已建立，不能重复建季                         |
| SEED_CONFLICT            | 两支球队占了同一个档位                               |
| NEW_SEASON_TOO_MANY      | 留级队加升级队超过 12 队上限                         |
| TEAM_IN_HISTORY          | 球队被历史赛季引用，不能删除                         |
| PROMOTE_TEAM_NOT_FOUND   | 勾选的升级队不在候选名录里                           |
