# tp144 联赛赛程与积分核算台

一个本地小工具：把参赛球队、比赛场地与整季赛程登记进来，打完的场次记上比分，页面立刻算出每个积分、净胜球与名次。一个赛季打完后按最终名次结算升级与降级、冻结存档，再按结果建立下一季；左侧可以随时切回历史赛季单独查看，旧赛程与旧名次跟当前赛季互不混淆。左侧切视图，右侧抽屉里增删改，所有数字都来自本机的数据文件，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5144>

端口固定为 `5144`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

左侧导航共六个视图，左上角的“查看赛季”下拉可以在所有赛季之间切换：

1. 概览：当前查看赛季的球队与场地数、赛程进度、已赛与待赛场次，下面列出最近五场赛果与积分榜前三
2. 赛季：升降级的结算台（详见下一节）
3. 球队：按参赛、退赛或外池筛选、按队名或城市搜索；新增时可以选择“编入本赛季”或“先放外池”；每支球队列出本季档位、归属与最终名次
4. 场地：以卡片列出场地名称、城市、容量、可用日、本季主场球队与本季/历史已排场次
5. 赛程：按轮次与状态筛选，逐场列出日期、时刻、对阵、比分、场地与状态；未打完的场次可以点登记比分
6. 积分榜：按名次列出档位、场次、胜平负、进球失球、净胜、积分与季末去向；历史赛季读冻结名次并带“名次已冻结”标记

任何一步不成立时，右上角弹出说明，并尽量把问题标到抽屉里对应的输入项上。

## 跨赛季怎么运转

### 球队的两个池子

- **赛季名单**：参加当前赛季的球队，在 `roster` 里各占一个档位（seedRank），档位在名单内互不重复。赛季中可以把状态改成“退赛”，退赛后名次无论排第几都按降级处理
- **外池**：不在当前赛季名单里的球队，是升级候选。外池球队也有一个参考档位，外池内部互不重复，用来给候选队排序
- 进行中的赛季可以把外池球队“编入本季”，或把没有赛程挂着的名单球队“移出外池”；已收官的赛季名单冻结，但仍可登记新的外池球队供下一季选用

### 结算升降级

在“赛季”视图操作，进行中的赛季页面分三块：

1. **完赛进度**：至少两支参赛队、有已赛场次、没有待赛与延期（取消的场次按不踢处理）才算打完；没打完会逐条列出还差什么
2. **规则与候选**：设置升级队数与降级队数；从外池候选里勾选与升级名额数量相同的球队。外池球队不够时页面明确提示，需要先去球队页登记
3. **去向试算表**：按当前实时名次给出每支球队的去向——
   - 垫底的 N 支（N = 降级队数）为**降级**，赛季中退赛的球队一律降级
   - 其余名次在降级线以上的为**留级**
   - 勾选的外池球队为**升级**，按勾选顺序依次填入降级队腾出的档位
   - 每支球队都带一句说明（最终第几名、落在降级线哪一侧、填第几个档位）

点击“确认完赛并冻结升降级结果”后：

- 最终积分榜整表快照（队名、名次、场次、胜平负、进球失球、净胜、积分、当时档位）封存进该赛季
- 每支球队的去向与原因一并冻结
- 该赛季变成“已收官”，赛程、比分、名次、规则全部只读，页面顶部出现深色冻结提示条

### 调整规则时说明哪些球队归属变了

进行中的赛季随时可以改升级队数或降级队数，点“应用并重算去向”后页面会：

- 保存新规则并立即重算去向
- 在规则卡片下方列出归属发生变化的球队，例如“海陵海燕（第 7 名）：留级 → 降级”
- 没有变化时明确说明“没有球队的去向发生变化”

已收官的赛季规则被冻结，不允许再改，避免历史去向与名次自相矛盾。

### 建立新一季

已收官且为最新一季时，赛季页底部出现“按升降级结果生成新赛季名单”：

- **留级队**：沿用上季档位（`carriedFrom` 记录来源赛季）
- **升级队**：按冻结去向填入降级队腾出的档位
- **档位空位**（例如升级名额少于降级名额、或 0 升级缩编）：草稿里逐条列出，每支球队的档位都可以在表格里手动调整
- **档位冲突**（同一档位排两支球队）会被拒绝并指明是哪两支队；漏排留级或升级球队也会被拒绝
- 新赛季名称自动按“春 → 秋 → 次年春”建议，可改；确认后新一季成为当前赛季，赛程从空表开始排

### 历史赛季回看

- 左上角下拉切到任一赛季，概览、球队、赛程、积分榜全部按该赛季的数据展示
- 已收官赛季显示冻结的最终名次与每支球队的去向，赛程 28 场（或当季实际场数）完整保留，所有写操作隐藏或被接口拒绝
- 冻结快保存的是收官瞬间的队名与数字，之后球队改名只影响新赛季，不会让旧名次里的队名变掉
- 不同赛季的赛程分别存放在各自的 `matches` 里，同一块场地的跨赛季赛程互不参与冲突判断

## 积分与排序口径

- 只统计状态为已赛的场次，延期、取消与待赛的场次不计入
- 积分按胜一场 3 分、平一场 1 分、负一场 0 分累加，规则记在每个赛季的 `points` 里
- 名次依次比较：积分高的在前 → 净胜球多的在前 → 进球多的在前 → 队名排序
- 净胜球等于进球数减失球数；积分榜随每次登记比分实时重算，收官后定格

## 登记口径

- 球队名称不重复、最长 24 个字；简称是两到四个大写字母且不重复；档位在 1 到 12 之间，且在所属池（赛季名单或外池）内不重复；主场必须是已登记的场地
- 新增球队可选编入当前赛季或先放外池；单个赛季参赛球队最多 12 支
- 场地名称不重复、最长 30 个字；容量在 100 到 200000 之间；至少要选一个可用日，且同一天不能重复勾选
- 赛程的轮次在 1 到 40 之间，日期要真实存在，开赛时刻写成两位小时加两位分钟；主队与客队不能是同一支，且都必须在该赛季名单内
- 同一轮里一支球队只能出场一次；同一天同一块场地两场比赛之间至少隔两小时（场地留空时按主队主场算）；取消的场次不占轮次与场地档期
- 比分只在状态为已赛时填写，取值是 0 到 99 的整数；状态不是已赛时填了比分会被拒绝
- 已收官赛季的赛程、比分、规则与名单全部只读
- 进过任一赛季名单或被历史赛程引用的球队不能删除，以免旧名次对不上；场地同理

## 数据存储

所有数据写在 `data/db.json`，顶层结构为 `{ meta, seasons, teams, venues }`：

- `meta.currentSeasonId` 指向当前赛季
- `seasons[]` 每个赛季含 `name / status（进行中|已收官）/ points / rules（promotionCount、relegationCount）/ roster[] / matches[] / finalTable（收官后冻结）/ promotion（收官后冻结）/ finalizedAt`
- `roster[]` 记录 `teamId / seedRank（本季档位）/ status（参赛|退赛）/ carriedFrom（上一个赛季 id）`
- `teams[]` 与 `venues[]` 是跨赛季的档案；球队当前展示的档位随查看的赛季取自对应 roster

落盘时先写临时文件再改名替换，写入过程中断不会把数据文件写坏；文件缺失或内容损坏时回落到初始数据。旧版扁平结构（`{ meta, teams, venues, matches }`）在首次读取时自动迁移成唯一一个进行中的赛季。

## 接口一览

| 方法   | 路径                              | 说明                                         |
| ------ | --------------------------------- | -------------------------------------------- |
| GET    | /api/health                       | 服务状态检查                                 |
| GET    | /api/summary                      | 概览数字、最近赛果与积分榜前三，可带 seasonId |
| GET    | /api/teams                        | 球队清单，支持 seasonId、归属状态与关键词     |
| POST   | /api/teams                        | 新增球队（inSeason=false 时登记为外池）       |
| PATCH  | /api/teams/:id                    | 修改球队档案、本季档位或参赛状态              |
| POST   | /api/teams/:id/join               | 外池球队编入指定赛季                          |
| POST   | /api/teams/:id/leave              | 名单球队移出赛季、退回外池                    |
| DELETE | /api/teams/:id                    | 删除从未进过赛季名单的球队                    |
| GET    | /api/venues                       | 场地清单，支持 seasonId 与关键词              |
| POST   | /api/venues                       | 新增场地                                     |
| PATCH  | /api/venues/:id                   | 修改场地                                     |
| DELETE | /api/venues/:id                   | 删除场地                                     |
| GET    | /api/matches                      | 赛程清单，支持 seasonId、轮次、状态与关键词   |
| POST   | /api/matches                      | 新增赛程                                     |
| PATCH  | /api/matches/:id                  | 修改赛程                                     |
| POST   | /api/matches/:id/result           | 登记比分，登记后自动标成已赛                  |
| DELETE | /api/matches/:id                  | 删除赛程                                     |
| GET    | /api/standings                    | 积分表；历史赛季返回冻结快照，可带 seasonId   |
| GET    | /api/seasons                      | 赛季清单（新到旧）与当前赛季 id               |
| GET    | /api/seasons/:id                  | 赛季详情：名单、冻结名次与升降级去向          |
| POST   | /api/seasons/preview              | 试算升降级去向，不落盘                        |
| PATCH  | /api/seasons/:id                  | 改赛季名称或升降级规则，返回去向变化清单      |
| POST   | /api/seasons/switch               | 切换当前查看的赛季                            |
| POST   | /api/seasons/finalize             | 完赛校验通过后收官，冻结名次与去向            |
| GET    | /api/seasons/new/draft            | 取新一季草稿：档位沿用、升级填空位            |
| POST   | /api/seasons                      | 按提交的名称与档位分配建立新一季              |

除赛季切换外，各列表与写操作都可以带 `seasonId` 指定赛季；不带时作用于当前赛季。接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
